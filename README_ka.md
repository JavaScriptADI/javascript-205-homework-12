# საშინაო დავალება 12 — fetch, async/await და შეცდომების დამუშავება

მოგესალმებით მეთორმეტე საშინაო დავალებაზე! 🎉

რეალურ აპლიკაციებში კოდის ნახევარი იმას ეძღვნება, რომ რაღაც არასწორად წავიდა: სერვერი პასუხობს 404-ს, Wi-Fi წყდება, პასუხი გვიან მოდის. ამ კვირას ააწყობთ პატარა **პროდუქტების მაღაზიას** ნაბიჯ-ნაბიჯ, და ასევე მოძებნით ბაგებს უკვე დაწერილ კოდში — ზუსტად ისე, როგორც რეალურ სამსახურში მოგიწევთ.

მონაცემები მოდის უფასო API-დან **https://dummyjson.com** (რეგისტრაცია არ სჭირდება).

## რას ივარჯიშებთ

* `fetch` და `response.ok` — 404 შეცდომა არ არის, სანამ *თქვენ თვითონ* არ აქცევთ შეცდომად
* `async` / `await` და `try` / `catch` / `finally`
* ჩატვირთვის, ცარიელი და შეცდომის მდგომარეობების ჩვენება გვერდზე
* `Promise.all` და როდის უნდა გაუშვათ მოთხოვნები პარალელურად
* რეალური შეცდომის წაკითხვა გამოცნობის ნაცვლად

## სწრაფი დაწყება

მიჰყევით [SUBMITTING_ka.md](./SUBMITTING_ka.md)-ის 1–4 ნაბიჯს — fork, თქვენი fork-ის clone, ბრენჩი, შემდეგ:

```bash
mkdir submissions/<your-username>
cp -r starter/* submissions/<your-username>/
```

გახსენით `submissions/<your-username>/index.html` ბრაუზერში, დატოვეთ DevTools ღია (`F12`) და დაიწყეთ დავალება 1-ით. **ყველაფერი, რასაც წერთ, სწორედ ამ ერთ ფოლდერში ცხოვრობს**, და სწორედ ეს ფოლდერი ბარდება.

> დავალება 1 ნებისმიერ დროს შეგიძლიათ შეამოწმოთ: `cd submissions/<your-username>` და შემდეგ `node check_1.js` (Node 18 ან უფრო ახალი). ის ყოველთვის მხოლოდ გვერდით მდებარე `api.js`-ს ამოწმებს.
